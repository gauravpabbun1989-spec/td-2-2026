## Learnings

- render-route.tsx builds an independent TanStack route tree rather than importing App.tsx's tree, so route drift between the two files never surfaces as a typecheck or build error — only as missing test coverage for unmirrored routes.
- When a test router intentionally mirrors a subset of production routes, the runtime-health KNOWN_PATHS set must cover every production route, not just the rendered ones, for the internal-link check to stay honest.
- A frozen-asset test that asserts byte-for-byte content must be updated in lockstep with any sitemap expansion; the ordered <loc> list is the most fragile assertion.
- Backend pipeline is clean: mops install, mops check --fix, mops build, and pnpm bindgen all pass with zero diagnostics for this project.
- backend.d.ts and backend.ts can disagree even immediately after pnpm bindgen regenerates both from the same backend.did — backend.ts exposes _initialize_access_control, _internet_identity_sign_in_start, _internet_identity_sign_in_finish while backend.d.ts omits all three. The two .ts files appear to be generated by different bindgen code paths; do not assume bindgen leaves them in sync.
